### Crad UI

- 카드 UI 란?
  : 카드란 이미지와 텍스트들을 담고 있는 작은 사각형
  : 해당 이미지와 텍스트들을 보다 디테일한 정보로 연결해주는 역할
  : 사용자에게 직관성을 주고, 복잡하고 다양한 정보를 통일감 있게 보여주기 쉽다.
- 카드 UI 장점
  : 정보를 분리시킬 수 있으며, 사용자들을 덩어리 감의 정보를 읽기 쉽다.
  : 사용자들이 자신의 흥미 요소에 쉽게 빠질 수 있게 도와준다.
  : 보는 이들에게 의미 있는 섹션으로 분리시키는 역할
- 시각적인 그룹핑
  : 많은 정보를 감싸기 때문에 복잡한 콘텐츠도 단순화 시킨 것 처럼 보이게 한다.
  : 대시보드, 포털 사이트, IT 사이트에서 많이 사용
- 생각보다 이쁘다
  : 카드 기반의 디자인은 시각적 요소에 매우 큰 영향을 받는 디자인
  : 인터렉션, 이미지, 그림자 등 다양한 디자인을 구현하기 좋은 레이아웃
  : 사용자들에게 즉각적인 반응 및 관심을 이끄는 역할하여 매력적인 디자인
- 모듈화에 최적화되어 있다
  : 카드 UI는 덩어리 감을 가지고 있어 컨텐츠간의 레이아웃 변동에 쉽게 대응
  : 기업에서 이벤트, 프로모션 및 기타 콘텐츠를 자유롭고 유연하게 대응하며 서비스 유지
- 뭘 해도 비슷해
  : 카드라는 스타일로 인해 어떤 디자인을 하든 부드러운 스타일의 디자인
  : 자사 사이트만의 특별함을 가져가기 어려움
- 지나친 방향은 독
  : 카드 UI에서의 다름은 결국 컬러 / 부피감 / 공간감의 차이
  : 이를 너무 과하게 하면 디자인은 특별하나 사용성 및 가독성이 저하
- 영역 확보가 어렵다
  : 공간을 강제적으로 좁게 사용한다는 치명적인 단점
  : 특히 모바일에서는 한정적인 공간에서 1px가 아쉬운 상황
- 대중적인 카드 UI
  : 많은 정보를 쉽게 그룹으로 묶어주는 가독성 디자인에서는 탁월한 효과
  : 많은 사이트에서 쉽게 접하여 사용자들에게 거부감 없는 디자인

### Full UI

- Full UI란?
  : 바닥에 디자인을 뿌리는 형태
  : 시선을 흐름을 유도하는 자연스러운 경험을 사용자에게 전달
  : 사용자에게 보여주고자 하는 부분을 최대한 노출시킬 수 있으며 다채로운 레이아웃 구성이 가능
- 플랫 미니멀 시대
  : 요즘 사용성 트렌드는 간편한 사용성과 극 심플함
  : 요소를 정의하고 바닥에 무심한 듯 올려 놓는 디자인 기법
- 바닥 UI 장점
  : 미니멀, 극심플 디자인을 추구하는 플랫 디자인에 최적화
  : 다채로운 디자인 방향을 정의하고 구현
- 시선의 흐름
  : 다양한 텍스트의 복잡함을 최소화시켜 디자인에 적용
  : 사용자에게 강제적으로 시선흐름을 유도하여 끊김없는 자연스러움 전달
- 몰입감을 전달한다
  : 고해상도 이미지 및 시원한 여백을 함께 사용
  : 명확한 정보와 함께 몰입도를 높이는 사용자 경험 전달
- 어떤 디자인도 가능하다
  : 바닥 UI는 디자인 속성에 구애받지 않고 모든 느낌의 디자인이 다채롭게 가능
  : 여러 색감을 조합해도 쉽게 녹아들도록 디자인이 가능
- 너무 자유롭다
  : 카드 UI 보다 상대적으로 자유롭게 디자인할 수 있지만 디자인 고민의 폭이 넓고 어려움
- 기본기가 중요하다
  : 여백, 라인, 크기, 컬러 등의 다양한 계층을 활용하여 그룹을 정의해야 한다.
- 디자인의 깊이
  : 사이트의 성향을 타지 않고 어떤 디자인이든 가능하지만 디자인의 깊이를 많이 고민해야 한다.

### 꼭 둘 중 1가지만 선택?

단점을 보완하며 다양한 디자인 스타일을 사용하되
9:1 / 8:2 처럼 전체적인 일관된 스타일은 유지

- 카드 UI 단점인 여백확보
  : Card UI 자체를 Full UI처럼 가로 영역을 확장하여 여백을 확보하는 디자인
  : Card UI의 그룹핑 확보 + Full UI의 넓은 가로여백 확보

- Full + Card
  : Full UI에서 많은 정보를 그룹하기 어렵거나 강조하는 등 명확한 계층을 주려는 경우
  : 특정 영역에서 Card UI를 사용하여 직관적인 UXUI를 전달

## 어떤 디자인을 하든 사용성에 집중하자

- 하나의 명확한 스타일을 유지하면서 통일성을 줘야한다.
- 내가 어떤 사이트를 디자인 할 것인지 파악하고 스타일을 잡아야한다.
- Full UI 보다 Card UI가 디자인을 풀기 쉽다.
- Full UI는 다채로운 디자인을 풀기 좋지만 기본기가 없다면 해결하기 어렵다.
- Card UI에서 선을 넘는 특별한 디자인은 오히려 독이 된다.

# 사용자를 위한 노력

디자이너는 사용자에게 쉽고 편한 익숙한 흐름과 패턴을 전달해야 한다.
UXUI를 특별하게 하기보단 익숙한 흐름을 연결해 주는 것이 좋다.

### UI 사용성

사용자가 액션을 취하기 전 눈에 잘 보이도록 디자인하는 것이 중요

### 1. 폰트

디자인을 위해 폰트를 작게 사용한다면 사용자는 경험을 하기 전에 이미 방향을 잃게 된다.

### 2. 버튼

버튼은 액션이 진행되기 전 사용자에게 행동을 유발하는 요소
버튼의 존재를 인식하지 못하면 구매 전환까지 진행되지 않는다.

### 3. 아이콘

아이콘은 배너를 제외하고 유일하게 시각 구조를 가지고 있는 UI
사용자에게 문구와 함께 그 의미를 극대화해 사용성을 강화

### 4. 여백

여백은 단순한 공간이 아닌 사용자에게 시선을 유도하는데 큰 효과
시선처리를 절제하고 중요한 항목을 집중시키는 요소

### 5. 컬러

컬러는 그 브랜드의 아이덴티티를 나타내는 방법 중 하나
사용자의 시선 유도를 자연스럽게 진행시킨다.

### 6. 각종 Elements 요소들

사용자들에게 보다 좋은 경험을 시켜주기 위해
크고 잘 보이도록, 잘 눌리도록 다양한 케이스들을 디자인
(default, hover, focus, 기본상태, 체크상태, 비활성화 상태 등)

## 단순한 디자인도 고민하자

- 클릭요소는 누를 수 있는 여백과 사이즈를 가져가자
- 폰트는 읽을 수 있는 기본 사이즈를 제공해야 한다.
- 나는 요소가 어디있는지 알지만 사용자는 모릅니다.
- 사용자가 시각으로 구분을 못한다면 사용성을 시작부터 틀린 것이다.
- 다른 사이트는 어떻게 디자인을 하고 있는지 충분히 고민하자.

# Resolution Guide (적응형 디자인) (PC)

- 고해상도와 저해상도를 최적화시켜 대응하는 방법으로 여러 사이트에서 사용하기 좋은 설계
- 반응형처럼 비율대로 사이즈가 줄어드는 것이 아닌 사이즈는 유지한 채 저해상도를 대응
- 모든 그리드는 12 Column 기준으로 제작
- 고해상도와 저해상도를 수용하기 위한 방법으로 반응형이 어려운 사이트에서 많이 사용
- 해상도에 따라 사이즈 변화가 아닌 그리드가 나눠져 콘텐츠를 보여주는 형식
- 반응하는 기점의 해상도에 접근하면 레이아웃이 변함
- 우측 그리드가 하단으로 떨어지면서 컨텐츠가 해상도에 맞게 대응

# Resolution Guide (반응형 디자인) (PC)

- PC 고해상도부터 Mobile 해상도까지 대응이 가능
- 해상도가 줄어들면 비율을 유지하면서 모든 해상도를 대응

### 최대 최저 해상도

- PC 고해상도 > 저해상도에서 1 Columns이 비율대로 사이즈가 변경. Gutters 및 Margins는 고정값을 유지
- 썸네일 이미지는 해상도에 따라 비율을 유지하며 사이즈가 변화
- 최대, 최소 해상도의 기준을 잡는다.
- PC > MO까지 반응할 것인지 PC 고해상도 > 저해상도만 반응할 것인지 정한다.
- 1920 최대 해상도 12 Column : Margins 20 / Columns 616 / Gutters 16
- 1320 최저 해상도 12 Column : Margins 20 / Columns 416 / Gutters 16

![alt text](<public/2/최대 최저 해상도-1.png>) ![alt text](<public/2/최대 최저 해상도-2.png>)

### 반응형 그리드 제작방법

- 고해상도와 저해상도를 수용하기 위한 방법으로 한 벌로 다채로운 디바이스 대응
- PC 고해상도 > 저해상도까지 비율대로 사이즈가 줄어들며
- 태블릿, 모바일 브레이크 포인트에서 적응형처럼 구조를 바꿔 최적화
- PC 웹디자인은 그리드 12 Columns 기준으로 제작
- 태블릿, 모바일은 브레이크 포인트로 레이아웃 및 마진 등 디자인이 변경
- 태블릿, 모바일은 그리드를 잡아도 되고 안잡아도 된다.
- 1920 최대 해상도 12 Column : Margins 20 / Columns 142 / Gutters 16
- 1320 최대 해상도 12 Column : Margins 20 / Columns 92 / Gutters 16
- 800 최대 해상도 12 Column : Margins 20 / Columns 81 / Gutters 16

# Layout Guide (기본 그리드) (PC)

- 풀해상도, 넓은 해상도, 좁은 해상도 3가지를 가장 기본형으로 추천
- 여러 성격의 사이트에서 사용하기에 가잔 무난한 해상도 그리드
- 모든 그리드는 12 Column 기준으로 제작

### 그리드 제작방법

- 모든 그리드는 Margins, Columns, Gutters 3가지 기준으로 잡는다.

1. Margins : 그리드 영역의 좌측 우측의 빈 공간. 고정 값 유지
2. Columns : 웹 화면에서 콘텐츠가 들어가는 부분. 반응형이 아닌 경우 고정 값 유지
3. Gutters : 콘텐츠가 들어가는 Columns의 사이 공간 값. 콘텐츠 간 간격으로 활용

![alt text](<public/2/그리드 제작방법-1.png>)

### 저해상도 1320 12 Columns

- 모든 해상도에서 균일한 디자인을 보여주고자 할 때 사용하는 보편적인 해상도
- 정보성 내용과 적당한 이미지를 보여주고자 할 때 밸런스 있게 만들 수 있는 레이아웃
- 일반적으로 가장 많이 사용하는 Gutter로 무난하게 디자인하기 용이
- 좁은 Gutters : Margins 20 / Columns 92 / Gutters 16
- 넓은 Gutters : Margins 20 / Columns 92 / Gutters 28

### 고해상도 1440 12 Columns

- 풀 화면은 부담스럽고 넓은 화면을 보여주고자 할 때 사용
- 이미지를 부각시키는 퍼포먼스로 사용자에게 집중시키기 좋은 레이아웃
- 저해상도(1320) 대응도 고려하여 제작해야 한다.
- 좁은 Gutters : Margins 20 / Columns 102 / Gutters 16
- 넓은 Gutters : Margins 20 / Columns 91 / Gutters 28

### 풀해상도 1920 12 Columns

- 풀해상도는 시원시원한 레이아웃을 사용하여 넓은 화면을 보여주고자 할 때 사용
- 글이 많고 내용이 많은 사이트 보단 이미지 중심 사이트에서 몰입감을 주는 레이아웃
- 반응형 및 적응형으로 제작해 저해상도 대응도 해야 한다.
- 좁은 Gutters : Margins 20 / Columns 142 / Gutters 16
- 넓은 Gutters : Margins 20 / Columns 131 / Gutters 28

# 다채로운 디바이스

### 대응 해야하는 디바이스

모바일 디자인은 기본적으로 각 디바이스의 기준이 되는 해상도를 고려하여 UI 설계
해상도는 가로 값을 기준으로 잡는다.

- Android
  : 320, 360, 412, 674
  : 360 X 740px 표준

- iOS
  : 320, 375, 390, 430
  : 375 X 812px 표준

### 해상도 대응

- 대표적으로 총 6개의 해상도 (320, 360, 375, 390, 432, 674)
- 해상도 대응은 최대한 공통을 유지
- 어쩔 수 없는 경우 변화의 폭을 줍니다.

![alt text](<public/2/해상도 대응-1.png>)

> 1. 430 이상 해상도가 커지면 레이아웃을 유지하고 좌우 여백만 벌리며 대응
> 2. 430 이상 해상도가 커지면 레이아웃이 변경되며 대응

## 모바일도 해상도 대응이 필요하다

- 최저 해상도로 디자인을 하면 넓히는 건 쉽습니다.
- Android, iOS를 한 세트로 생각해야 합니다.
- 이미지를 1벌로 가져갈 고민을 하고 대응책을 생각합니다.
- 분기를 태우지 않는 환경에서 해상도 대응을 고민해야 합니다.
- 고정을 어디에 시킬지 정의합니다.
